# Flutter 管理台 UI 构思

## 产品方向

管理台不是通用服务器面板，而是围绕一次核心判断设计：项目现在是否健康，如果不健康，最近一次部署发生了什么，以及下一步能做什么。

视觉风格采用安静、偏工具型的界面：中性背景、单一蓝色强调色、紧凑列表、清晰状态文字。状态不能只用颜色表达；每处状态同时显示图标和文本。

## 信息架构

桌面端使用左侧项目导航和右侧详情；手机端改为项目列表页进入详情页，不保留永久侧栏。

```text
项目
├── 概览：运行状态、当前 commit、最近部署、访问端口
├── 部署：release 与 deployment 时间线、同步、部署、回滚
├── 日志：有限历史、暂停滚动、复制、行数选择
└── 设置：Git、分支、触发规则、环境变量、删除项目

系统
├── SSH 凭据：仅显示 id、指纹与引用项目，不显示私钥
├── 存储：可用空间、release 保留数、最近备份
└── 服务：ProjectDeployer、Docker 与轮询状态
```

## 核心页面

### 项目列表

- 顶部只保留“新建项目”主操作。
- 每行显示项目名、运行状态、分支、短 commit、最近部署时间和失败原因摘要。
- 默认按“需要处理、部署中、正常、已停止”排序，不做无意义 KPI 卡片。
- 空状态直接提供创建项目入口和 manifest 示例说明。

### 项目详情

详情页标题区展示项目名、`仓库 · 分支`、运行状态，以及同步、重启和更多操作。停止、回滚、删除放入次级菜单；删除要求输入项目 id，并单独确认是否清理 volume。

概览主体分两列：左侧是当前 release 和容器事实状态，右侧是最近部署时间线。窄屏按这个顺序纵向排列。

### 创建与编辑

使用分步表单，但只分成三个有业务意义的步骤：

1. 来源：名称、仓库 URL、分支、SSH credential。
2. 触发：自动或手动、轮询间隔、include/exclude 路径。
3. 环境与确认：变量名和值、连接校验、最终摘要。

编辑页复用同一表单。密钥值不会回显；环境变量已存在时只显示名称，留空代表保持原值需要后端后续提供对应更新语义。

### 部署与日志

- release 时间线明确区分 observed、ready、running、failed、skipped。
- 每次 deployment 显示动作、commit、开始/结束时间和可展开错误。
- 日志使用等宽字体、有限缓存；提供暂停自动滚动、复制和下载当前内容。
- Flutter Web 第一版轮询项目详情和日志；后端 WebSocket 完成后再切实时流，不提前引入双通道状态同步。

## 响应式规则

- 大于等于 900 px：固定项目侧栏，详情区最大宽度保持可读。
- 600–899 px：侧栏缩窄，仅显示项目名与状态；详情双列变单列。
- 小于 600 px：独立列表与详情导航，底部操作避免与系统手势区域冲突。
- 所有点击目标至少 44 px；表单字段在手机端保持单列。

## Flutter 实现建议

- 使用 Material 3，`NavigationRail`、`Scaffold`、`ListView`、`Card`、`SegmentedButton`、`AlertDialog` 等系统组件。
- 路由保留可复制 URL：`/projects`、`/projects/:id`、`/projects/:id/deployments`、`/settings/credentials`。
- 页面状态局部化；API client、会话与全局项目缓存才进入共享状态，不使用无边界的全局 `EnvironmentObject` 式设计。
- 所有文本从第一天进入 ARB，先提供简体中文和英文。
- 状态刷新使用一个可取消的页面级轮询任务；切换项目或离开页面时立即取消。

## 第一版范围

第一版实现项目列表、创建/编辑、详情、部署时间线、生命周期操作、有限日志、SSH credential 元数据、存储状态和备份入口。不实现图表大屏、主题市场、多用户、通知中心和拖拽编排。
